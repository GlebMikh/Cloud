# Глебот в виде Slack-приложения

Второй контур: постоянный процесс, который слушает события Slack и реагирует
за секунды. Рубрику классификации и шаблоны ответов он не дублирует — читает
те же `references/`, что и часовой обход. Правка тона в одном месте меняет
поведение обоих.

## Что это даёт сверх часового обхода

Очевидный выигрыш — мгновенная реакция на прямой тег. Менее очевидный и
более важный: **петля одобрения замыкается за секунды.** В часовом режиме ты
жмёшь ✅ в 14:05, а ответ уходит в тред в 15:07. Здесь — сразу. Именно это
превращает согласование из процедуры в жест.

## Установка

### 1. Приложение в Slack (нужны права админа)

1. [api.slack.com/apps](https://api.slack.com/apps) → **Create New App** →
   **From an app manifest** → выбрать воркспейс Cobaltlab.
2. Вставить целиком содержимое `bot/manifest.yaml`, создать.
3. **Basic Information → App-Level Tokens → Generate Token and Scopes**:
   имя любое, скоуп `connections:write`. Полученный `xapp-…` → `SLACK_APP_TOKEN`.
4. **OAuth & Permissions → Install to Workspace**. Полученный `xoxb-…` →
   `SLACK_BOT_TOKEN`.
5. **Basic Information → App Credentials → Signing Secret** → `SLACK_SIGNING_SECRET`.
6. Пригласить бота в каналы: `/invite @Глебот` в `#разработка-обсуждение`
   и `#qa-баги`. Без этого он не увидит ни одного сообщения — в отличие от
   пользовательского токена, бот видит только то, куда его позвали.

### 2. Ключи

```bash
cp bot/.env.example .env
$EDITOR .env          # проставить токены, ANTHROPIC_API_KEY, при желании Jira
```

### 3. Запуск

```bash
pip install -r bot/requirements.txt
set -a && . ./.env && set +a
python bot/app.py      # запускать из корня репозитория — там лежит рубрика
```

Socket Mode не требует публичного адреса и входящего трафика, поэтому
подойдёт что угодно, что умеет держать процесс: Fly.io, Railway, любой VPS,
да хоть ноутбук для первой проверки.

Перед первым запуском стоит прогнать `python bot/test_smoke.py` — он
проверяет дедупликацию, фильтр и отрисовку карточки, не трогая сеть.

## Как пользоваться

Бот присылает карточку в личку. Решение принимается одним из трёх способов:

| Реакция на карточке | Слово | Что произойдёт |
|---|---|---|
| ✅ | `ок`, `да`, `+`, `го` | Ответ уйдёт в исходный тред |
| 🎫 | `ок+жира`, `+тикет` | Ответ уйдёт в тред и заведётся баг в Jira |
| ❌ | `нет`, `отмена` | Черновик отменён, в канал ничего не уходит |
| — | любой другой текст | Правка: бот перепишет и пришлёт заново |

Слово можно написать **и в треде карточки, и просто сообщением в личке** —
в разговоре с самим собой второе естественнее, и оно работает. Когда решения
ждут несколько карточек, начни с номера: `7c1a ок`. Номер ищется по началу,
так что ошибиться регистром или оборвать его не страшно.

Угадывать адресата, когда карточек несколько, бот не станет — перечислит их
и переспросит. Ценой ошибки был бы чужой ответ в рабочем канале.

Перед публикацией бот перечитывает исходный тред. Если ты успел ответить сам,
он не полезет следом, а напишет об этом в треде карточки.

## Настройки, которые стоит знать

**`AUTO_REPLY_ON_MENTION`** — единственный переключатель, который меняет
поведение принципиально. При `true` прямой тег получает мгновенный ответ без
твоего участия («увидел, передаю Глебу»), а тебе уходит уведомление постфактум.
Остальные классы всё равно идут через одобрение. Включать стоит тогда, когда
ты перестанешь править черновики MENTION — до тех пор выигрыш не стоит риска.

**`MARKER_EMOJI`** — реакция-метка «разобрано». По умолчанию 🤖. Не бери
эмодзи, которым пользуются люди: 👀 в `#qa-баги` уже стоит на баг-репортах
от живых коллег, и бот принял бы чужие метки за свои.

**`GLEBOT_MODEL`** — по умолчанию `claude-opus-5`. Стоимость держит в узде не
модель, а дешёвый фильтр: через Claude проходит не весь поток канала, а
единицы сообщений в час. Рубрика (около 9000 символов) уходит в prompt cache
с часовым TTL, поэтому повторные вызовы стоят примерно десятую часть первого.
Считать `cache_read_input_tokens` в логах стоит в первый же день: если он
стабильно нулевой, кеш не работает и цена вырастет на порядок.

## Сводка, добор истории и уборка

Три вещи бот делает не от событий, а сам по часам:

- **Добор истории при старте.** Slack не переигрывает пропущенные события:
  всё, что произошло, пока процесс лежал, для него не существует. Поэтому
  при каждом запуске бот прочитывает последние `BACKFILL_HOURS` часов и
  разбирает то, на чём ещё нет метки. Без этого любой деплой означал бы
  навсегда потерянный кусок канала.
- **Ежедневная сводка** в `DIGEST_AT`: что ждёт решения, что обсуждали в
  каналах-наблюдателях, что сделано за сутки. Если говорить не о чем,
  сводка не отправляется.
- **Отмена протухших карточек** старше `DRAFT_EXPIRY_HOURS` — с припиской
  в тред карточки, чтобы отмена не прошла молча.

## Что бот не делает

- Не ищет дубли в Jira автоматически перед созданием. `jira.find_similar()`
  готов, но по реакции 🎫 тикет заводится сразу: лишний вопрос в момент,
  когда ты уже принял решение, раздражает больше, чем редкий дубль.
- Не переживает потерю `glebot.sqlite3`. База — единственное место, где
  живут ожидающие карточки; на постоянном хосте её стоит положить на диск,
  который переживает деплой.

## Отношения с часовым обходом

Два контура могут работать одновременно, и это даже полезно на переходный
период: бот отвечает за скорость, часовой обход — за то, что ничего не
потерялось, пока процесс лежал.

Общая метка-реакция не даёт им отвечать дважды на одно сообщение: оба ставят
🤖 до отправки карточки и оба пропускают уже помеченное. Если контуры
разъедутся по метке (разный `MARKER_EMOJI`), дубли пойдут немедленно —
это первое, что нужно проверить при странном поведении.
