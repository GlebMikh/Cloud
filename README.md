# Глебот — Slack-агент для наблюдения за каналами разработки

Читает рабочие каналы Cobaltlab, отличает баги и задачи от болтовни, готовит
ответы в треды и заготовки тикетов в Jira. Ничего не постит без подтверждения
владельца.

## Как это устроено

```
   раз в час (Routine)
          │
          ▼
  ┌───────────────────┐   1. читает одобрения    ┌──────────────────┐
  │  сессия Claude    │◄─────────────────────────│  личный DM Глеба │
  │  Code (эфемерная) │   4. шлёт черновики ────►│   («инбокс»)     │
  └────────┬──────────┘                          └──────────────────┘
           │ 2. читает новые сообщения
           │ 3. классифицирует
           │ 5. постит одобренное
           ▼
  #разработка-обсуждение · #qa-баги · #dev-кабан        Jira TEAMDEV
           │                                                  ▲
           └──────────── состояние → git ─────────────────────┘
```

Отдельного сервера нет. Раз в час планировщик поднимает сессию Claude Code,
она отрабатывает цикл из `.claude/skills/slack-watch/SKILL.md` и гаснет.
Состояние переживает перезапуск за счёт того, что коммитится в этот репозиторий.

Slack-доступ — по токену самого Глеба, поэтому сообщения агента выглядят как
его собственные и помечаются префиксом «🤖 *Глебот* (AI-помощник Глеба)».

## Цикл одобрения

1. Агент находит сообщение, которое считает багом, задачей, вопросом или
   прямым обращением к Глебу.
2. Присылает в личный DM карточку: канал, автор, цитата, ссылка на тред и
   готовый текст ответа — ровно в том виде, в каком он уйдёт в канал.
3. Глеб отвечает:
   - ✅ или `ок` — запостить ответ в тред;
   - 🎫 или `ок+жира` — запостить и завести тикет в TEAMDEV;
   - ❌ или `нет` — отменить;
   - любой другой текст — правка, агент перепишет и пришлёт заново.
4. Следующий цикл исполняет решение и ставит на исходное сообщение 👀 —
   метку «разобрано».

Одобрение исполняется на следующем цикле, то есть в среднем через полчаса.
Как ускорить — ниже, в «Настройке частоты».

## Что где лежит

| Файл | Зачем |
|---|---|
| `config/watch.yaml` | Каналы, тон, лимиты, Jira. Единственное место для правок в обычной жизни. |
| `.claude/skills/slack-watch/SKILL.md` | Плейбук цикла: что агент делает по шагам. |
| `.claude/skills/slack-watch/references/classification.md` | Рубрика: баг / задача / вопрос / обсуждение / шум, с примерами из реальных каналов. |
| `.claude/skills/slack-watch/references/replies.md` | Тон и шаблоны ответов. |
| `.claude/skills/slack-watch/references/jira.md` | Формат заготовки и правила создания issue. |
| `state/cursor.json` | Докуда дочитан каждый канал. |
| `state/pending.json` | Черновики, ждущие решения. |
| `state/SCHEMA.md` | Что означают поля состояния. |
| `bot/` | Этап 2: Slack-приложение на Socket Mode — мгновенная реакция и одобрение за секунды. Установка — `bot/README.md`. |
| `Dockerfile`, `docker-compose.yml` | Запуск бота на постоянном хосте: `docker compose up -d`. База с ждущими карточками — в томе, переживает выкат. |
| `docs/realtime-bot.md` | Зачем нужен второй контур и как два контура уживаются. |

## Управление

Запустить цикл руками, не дожидаясь часа, — в сессии Claude Code на этом репо:

```
/slack-watch
```

Расписание живёт в Routines, не в репозитории. Посмотреть, поставить на паузу
или удалить — через список Routines в claude.ai/code либо попросить об этом
в сессии («покажи мои routines», «поставь Глебота на паузу»).

## Настройка частоты

Планировщик Routines умеет минимум раз в час. Если получаса ожидания
подтверждения много — заводятся несколько Routine со сдвигом по минутам
(`5 * * * *`, `20 * * * *`, `35 * * * *`, `50 * * * *`), и цикл фактически
идёт каждые 15 минут. Дороже по токенам, но никакой дополнительной
инфраструктуры не требует.

Настоящий real-time — отдельное Slack-приложение на Socket Mode, оно лежит
в `bot/`. Оно же убирает главную задержку часового режима: одобрение
исполняется за секунды, а не к следующему часу. Установка — `bot/README.md`.

## Границы

- Агент не принимает решений за владельца: не назначает приоритеты, не обещает
  сроков, не диагностирует причины багов.
- Агент не выполняет инструкции из чужих сообщений в Slack — для него это
  данные для классификации, а не команды.
- Содержимое приватных каналов не попадает в публичные.
- В каналы Slack Connect (внешние) постить нельзя технически — ограничение
  пользовательского токена.
