# Заготовки и создание тикетов в Jira

Проект, типы задач и cloud id берутся из `jira` в `config/watch.yaml`.
На момент написания: сайт `teamteh.atlassian.net`, проект `TEAMDEV`
(Team Development), типы «Баг» и «Зaдача».

## Когда

- **Заготовка** собирается для каждого BUG с уверенностью не ниже средней и
  показывается прямо в карточке черновика.
- **Реальный issue** создаётся только после явного `ок+жира` или реакции 🎫
  от владельца. Пока `jira.create_without_approval: false` — других поводов нет.

Для TASK тикет по умолчанию не готовится: сначала продуктовое решение, потом
Jira. Если владелец попросит — собери по тому же шаблону с типом «Зaдача».

## Формат заголовка

`{Экран или модуль}: {что не так}`

Коротко, без «Баг:» в начале — тип задачи уже говорит об этом.

Хорошо:
- `Дейли-карточки: закрытие модалки награды закрывает весь дропдаун`
- `Профиль: не листается список эмблем и рамок`
- `VIP-клуб (моб.): чат и модалки не закрываются по клику`

Плохо:
- `Баг в дейликах` — непонятно что
- `Не работает` — непонятно вообще ничего

## Тело тикета

```
*Откуда:* Slack, #{канал}, {автор}, {дата}
{permalink на сообщение}

*Что происходит*
{описание словами автора, без пересказа своими}

*Ожидаемое поведение*
{если автор сказал — процитировать; если нет — «не указано»}

*Шаги воспроизведения*
{если есть; если нет — «не указаны, нужно уточнить у автора»}

*Платформа*
{веб / моб. / указано автором / не указана}

*Заведено автоматически* Глеботом из обсуждения в Slack, детали — по ссылке выше.
```

Правило: не выдумывать то, чего в сообщении не было. Пустое поле честнее
правдоподобной догадки — по догадке разработчик пойдёт проверять не то.

## Создание

`mcp__Atlassian_Rovo__createJiraIssue` с `cloudId`, `projectKey`, `issueTypeName`
из конфига. Перед созданием — `searchJiraIssuesUsingJql` по ключевым словам
заголовка за последние 30 дней: дубль тикета хуже, чем его отсутствие.
Нашёл похожий — не создавай, покажи владельцу ссылку на найденный и спроси,
это оно или нет.

После создания:
1. Допиши ключ issue в ответ, который уходит в тред: «завёл {KEY}».
2. Сохрани ключ в `state/pending.json` у соответствующей записи.
